# 암장 혼잡도 트래커 — 설계 문서

작성일: 2026-10-23

## 1. 왜 만드는가

사용자는 서울에서 클라이밍을 주로 한다. 크루/동호회 정모 한 번에 보통 10명 정도가 오는데, 같은 날 같은 암장에 2~3개 크루가 겹치면 30명 가까이 몰려서 문제 하나 붙으려고 오래 기다려야 한다.

이 앱은 **소모임과 당근 모임에 올라온 클라이밍 정모 일정을 자동으로 모아서, 이번 주에 내가 자주 가는 암장이 언제 얼마나 붐빌지 미리 보여준다.** 사용자는 매일 한 번 열어서 이번 주 상황을 확인하고 운동 갈 날/암장을 고른다.

## 2. 목표 / 비목표 / 실패 기준

**목표**
- 서울 전체 암장을 대상으로 소모임과 당근 모임의 클라이밍 정모 일정을 수집한다.
- 즐겨찾기한 암장마다 이번 주 요일별 예상 인원을 막대그래프로 보여준다.
- 인원은 사용자의 운동 시간대 기준으로 센다(기본값: 평일 18:00 이후, 주말 14:00 이후).

**비목표 (이번 범위 아님)**
- 문토, 인스타그램, 카카오톡 오픈채팅 수집 (조사 결과 기술적·정책적으로 어렵거나 불가능 — 6절 참고)
- 알림/푸시
- 회원가입, 로그인, 계정 동기화
- 앱스토어 배포
- 서울 외 지역
- 일반 이용객(크루가 아닌 개인) 수 추정

**실패 기준 (돌아가더라도 실패인 경우)**
- 실제로 크루가 몰리는 날인데 그래프에 안 잡힌다 (장소 매칭 누락이 가장 큰 위험).
- 보드게임 등 클라이밍이 아닌 모임이 인원으로 잡혀서 숫자를 믿을 수 없다.
- 수집이 소모임/당근 쪽에 부담을 줄 만큼 잦아서 차단당한다.

## 3. 사용자와 사용 방식

- 사용자 본인과 크루 친구들 몇 명만 쓴다. 공개 서비스가 아니다.
- 링크를 공유하면 바로 쓰는 웹앱. 폰 홈 화면에 추가해서 앱처럼 쓴다(PWA).
- 매일 한 번 열어서 이번 주를 훑어보는 용도.

## 4. 화면 (사용자가 C안으로 결정)

**메인: 내 암장 카드**
- 즐겨찾기한 암장마다 카드 하나.
- 카드에 이번 주(오늘 포함 앞으로 7일, 또는 월~일 — 빌더 판단) 요일별 막대그래프.
- 막대 높이 = 그날 **내 시간대 안에 시작하는** 정모의 참석 인원 합계.
- 붐비는 날은 진한 색으로 강조. 기준값(예: 20명 이상)은 빌더가 정하되 설정에서 바꿀 수 있으면 좋다.
- 막대(요일)를 누르면 그날 정모 목록: 시작 시간, 모임 이름, 참석 인원/정원, 출처(소모임/당근), 원본 링크. 시간대 밖 정모도 흐리게 함께 보여준다.

**암장 추가**
- 서울 암장 목록에서 이름으로 검색해 즐겨찾기 추가/삭제.

**설정**
- 운동 시간대: 평일 시작 시각, 주말 시작 시각 (기본 18:00 / 14:00).
- 즐겨찾기와 설정은 브라우저(localStorage)에 저장. 로그인 없음.

**마지막 수집 시각**을 화면 어딘가에 표시해서 데이터가 얼마나 최신인지 알 수 있게 한다.

## 5. 데이터 수집

### 5.1 소모임 (somoim.co.kr) — 로그인 없이 웹에서 가능, robots.txt 전체 허용

- **모임 찾기:** `https://www.somoim.co.kr/groups/search/서울특별시/{구}/클라이밍` 페이지가 서울 25개 구별로 있다(검색 사이트맵 `sitemap-kr-search.xml.gz`에서 확인). 각 페이지에 모임 링크 `/{uuid}{숫자}` 형태가 수십 개 있다(마포구 예: 94개). 구 사이에 같은 모임이 겹칠 수 있으니 중복 제거.
- **정모 일정:** 모임 페이지(`https://www.somoim.co.kr/{groupId}`)가 서버 렌더링 HTML이고 "정모 일정" 영역에 각 정모의 제목, 날짜/시간(예: "10/31(토) 오후 7:00", "내일 오후 2:00"), 장소 텍스트(예: "클라이밍 파크 종로"), 참석/정원(예: "4 / 10")이 있다.
- **날짜 파싱 팁:** 화면 날짜는 "내일" 같은 상대 표현이 섞인다. 정모 썸네일 이미지 URL에 `…{groupId}202610311900s1.png`처럼 절대 일시(YYYYMMDDHHmm, KST로 보임)가 들어 있어 이걸 우선 쓰면 좋다. 빌더가 검증할 것.
- Next.js RSC 페이로드(`self.__next_f`)에 구조화된 데이터가 있을 수 있으니 HTML 파싱보다 안정적이면 그쪽을 써도 된다.

### 5.2 당근 모임 (daangn.com) — 로그인 없이 웹에서 가능, `/kr/group/` 경로는 일반 크롤러에 허용

- **모임 찾기:** `https://www.daangn.com/kr/search/group/?in={동이름}-{regionId}&q=클라이밍` 으로 지역별 검색이 된다(`q` 파라미터 확인됨, `search`/`keyword`는 무시됨). 결과 페이지에 JSON-LD `ItemList`로 모임 URL과 이름이 들어 있다. 서울 동/구별 regionId 목록을 확보해 훑어야 한다 — 방법은 빌더 판단. 보조로 `https://www.daangn.com/kr/group/sitemap-detail.xml.gz`(약 2,200개, 일부만 포함)에서 이름에 클라이밍/볼더/암벽이 들어간 모임도 추가.
- **정모 일정:** 모임 페이지 HTML 안에 `"meetups":[…]` JSON이 있다. 필드: `id`, `name`, `meetAt`(UTC ISO), `currentParticipantsNumber`, `maximumParticipantsNumber`, `progressStatus`(OPENED/CLOSED), `groupOnly`, `placeTag`(있으면 `name`, `coordinate`, `addressText`). 모임 자체에도 `region` 정보가 있다.
- `groupOnly: true`인 일정도 시간·인원·장소 태그는 보인다 → 포함한다.
- `placeTag`가 없으면 일정 이름(예: "성수 더클라임 낮클", "종로 피커스 퇴근클")에서 암장을 찾아야 한다.
- 모임 페이지에 최근 일정 몇 개만 실리는지, 전체 일정이 다 실리는지 빌더가 확인할 것. 부족하면 모임의 일정 탭 페이지를 추가로 본다.

### 5.3 수집 주기와 예의

- **비용 0원이 원칙(사용자 결정).** 수집기는 Vercel이 아니라 **GitHub Actions 예약 실행(schedule)** 에서 돌리는 독립 Node/TypeScript 스크립트로 만들고, 결과를 Neon Postgres에 직접 쓴다. 웹앱(Vercel Hobby)은 DB를 읽기만 한다.
- 하루 3회 정도(예: 07:00, 12:00, 18:00 KST). GitHub Actions 예약은 몇 분~수십 분 늦어질 수 있는데 이 용도엔 괜찮다. 수동 실행(workflow_dispatch)도 열어 둔다.
- 요청 사이에 간격을 두고(예: 1초 이상), 동시 요청을 적게 유지. 일반적인 브라우저 User-Agent 사용, robots.txt에서 막힌 경로는 쓰지 않는다.
- 한 번 실행에 수백 페이지를 보므로 수십 분 걸릴 수 있다. GitHub Actions 작업 시간 제한(6시간) 안에서 충분하다. 공개 저장소면 Actions 무료 무제한, 비공개면 월 2,000분 무료 한도 안에 들어오는지 빌더가 확인(초과 우려 시 하루 2회로 줄이거나 저장소 공개 — 저장소 공개 여부는 사용자에게 확인).
- 모임 목록(어떤 모임이 있는지)은 정모 일정만큼 자주 바뀌지 않으므로 하루 1회만 갱신하고, 나머지 실행에선 알려진 모임 페이지만 다시 보는 식으로 줄여도 된다 — 빌더 판단.
- 수집 실패가 나도 이전 데이터는 유지하고, 마지막 성공 시각을 기록한다.

## 7. 암장 매칭과 필터링 — 이 앱의 핵심 정확도

**암장 목록**
- 서울 클라이밍 암장 목록(이름, 지점, 주소, 좌표, 별칭 목록)을 직접 만들어 둔다. 처음엔 수동으로 정리한 시드 데이터(주요 브랜드: 더클라임, 클라이밍파크, 서울숲클라이밍, 피커스, 손상원클라이밍 등의 서울 지점 + 독립 암장)로 시작한다.
- 별칭 예: "클팍 종로" = "클라이밍 파크 종로" = "클라이밍파크 종로점", "더클 강남" = "더클라임 강남", "피커스 신촌" = "피커스클라이밍신촌".

**매칭 순서**
1. 당근 `placeTag`가 있으면 좌표/이름으로 매칭.
2. 장소 텍스트(소모임) 또는 일정 이름(당근)을 정규화(공백/특수문자 제거, "점"/"클라이밍" 등 접미어 처리)한 뒤 별칭 사전과 비교.
3. 브랜드만 있고 지점이 없으면("더클 7시") 모임의 주 활동 지역으로 추정하거나, 추정이 안 되면 미매칭으로 둔다.

**미매칭 처리**
- 매칭 안 된 일정은 버리지 말고 따로 저장한다. 관리용 간단한 화면(또는 목록 페이지)에서 미매칭 장소 텍스트를 빈도순으로 보고, 별칭 사전에 추가할 수 있으면 좋다. 별칭을 추가하면 다음 수집 때부터 반영된다.

**클라이밍 아닌 일정 거르기**
- "클라이밍"으로 검색해도 보드게임 모임 등이 섞인다. 장소가 암장 목록에 매칭되는 일정만 그래프에 넣는다 — 이것만으로 대부분 걸러진다.

## 8. 인원 계산

- 정모 하나의 인원 = 현재 참석 신청 인원(`current`). 정원은 목록에서 함께 보여주되 합계에는 쓰지 않는다.
- 당근의 `CLOSED`(마감) 정모도 포함한다 — 보통 정원이 차서 마감된 것이므로(Claude 판단). 취소/삭제되어 페이지에서 사라진 정모는 제외한다.
- 별칭을 추가하면 기존 미매칭 정모도 다시 매칭한다(Claude 판단).
- 같은 날, 같은 암장, 사용자 시간대 안에 **시작하는** 정모들의 참석 인원을 더한다.
- 시간대는 클라이언트(브라우저)에서 사용자 설정으로 필터링하므로, 서버는 모든 일정을 시간 정보와 함께 내려준다.
- 모든 시간은 KST 기준으로 표시하고 계산한다.
- 같은 정모가 두 플랫폼에 올라오는 경우는 드물다고 보고 처음엔 합치지 않는다(빌더 판단으로 단순 중복 제거 가능).

## 9. 기술 선택 (Claude가 정함, 사용자 동의)

- Next.js (App Router, TypeScript) 웹앱 + PWA 매니페스트
- Vercel Hobby(무료) 배포 — 웹앱만
- 수집: GitHub Actions 예약 실행에서 도는 TypeScript 스크립트 (같은 저장소, 웹앱과 DB 접근 코드 공유)
- 데이터베이스: Neon Postgres 무료 플랜 (Vercel Marketplace로 연결, 접속 정보는 GitHub Secrets에도 등록)
- 데이터 단위(제안): 암장(gyms, 별칭 포함), 모임(groups: 출처, 외부 ID, 이름, URL), 정모(meetups: 출처, 외부 ID, 모임, 시작 시각, 참석/정원, 원본 장소 텍스트, 매칭된 암장 또는 null, 마지막 확인 시각). 구체적인 스키마는 빌더 판단.
- 정모는 (출처, 외부 ID)로 upsert해서 인원 변화를 반영한다. 소모임 정모의 외부 ID가 명확하지 않으면 (모임 ID + 시작 시각)으로 만든다.

## 10. 빌더에게 맡기는 것

- 크롤러 구현 방식(HTML 파싱 vs 페이로드 JSON), 배치 분할, 재시도
- 당근 서울 regionId 목록 확보 방법
- 암장 시드 데이터 정리(가능한 한 서울 전체)
- 그래프 라이브러리, 색 단계, 화면 디자인 세부
- 이번 주 범위를 "오늘부터 7일"로 할지 "월~일"로 할지
- 관리용 미매칭 화면의 형태(보호는 간단한 비밀 키 정도면 충분)
- 테스트 범위: 날짜 파싱, 암장 매칭, 인원 합계는 꼭 테스트. 크롤러는 저장해 둔 HTML 샘플로 테스트.
